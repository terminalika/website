## how it works

<Steps>

1. **The agent works. You play.**

   Start a task in Claude Code, Pi, Aider or Cursor, open `terminalika` in
   the next pane and pick Snake, Tetris, 2048 or Minesweeper. They are
   built to be dropped mid-move; that's the point. In pi there is no next
   pane: the [pi plugin](/pi/) opens the game right over the conversation
   with `/play`.

2. **It listens for the agent.**

   terminalika tails the agent's own session files - no hooks, no proxy,
   nothing leaves your machine (Cursor and anything else post one line from
   a hook; the pi plugin gets pi's own `agent_settled` event). Two events
   matter: *finished* and *needs your input*. Either one freezes the game
   with a one-line notice in the agent's colour.

3. **The agent is one pane away.**

   The game is already paused - switch panes, answer, come back whenever.
   The game and your score are where you left them. In pi, not even that:
   `ESC` parks the game, you answer in the same window, `/play` brings it
   back exactly where it was. No desktop popups, no background process:
   terminalika is a game launcher, not a notification service.

</Steps>

## the science of the small wait

Interruption research has measured "just checking" for twenty years: about
23 minutes to get back to an interrupted task, 10-15 minutes before a
developer edits code again, and a screen attention span now around 47
seconds. terminalika doesn't make the wait shorter; it keeps it from
turning into an interruption. [The studies, and what they actually say →](/research/)

## faq

<div class="tk-faq">
<details>
<summary>Does it slow down or interfere with my agent?</summary>

No. It reads the transcript files the agent already writes to disk. No
proxy, nothing injected, nothing sent anywhere.

</details>
<details>
<summary>Which agents?</summary>

Claude Code, Pi Agent and Aider natively. Cursor CLI - and any tool with a
hook - through `terminalika notify`. See [agents](/agents/). In pi the
games can also run *inside* the agent itself, as the
[pi extension](/pi/) - no CLI at all.

</details>
<details>
<summary>Do I have to set up any AI agents?</summary>

No. Setup asks up front - answer "just play" and it skips agent
configuration entirely: a plain retro-game launcher, nothing watched,
nothing to notify. Turn agent tracking on later any time with
`terminalika --setup`.

</details>
<details>
<summary>Will it pause for every little thing?</summary>

Two events only: the agent *finished*, or it *needs your input*. Tool calls
and subagent chatter are ignored; the same event within three seconds is
deduplicated. The [pi extension](/pi/) is even narrower: pi's own
`agent_settled` event, nothing else.

</details>
<details>
<summary>Where do notifications show up?</summary>

In the game, and only there: the pause notice, a corner banner if you
turned auto-pause off, a toast on the home screen. In the
[pi extension](/pi/), the same pause notice - or a toast pointing at
`/play` if you chose the settle mode. No desktop notifications either way.

</details>
<details>
<summary>Can I answer the agent from inside the game?</summary>

With the [pi plugin](/pi/), yes: the game is an overlay inside pi itself,
so `ESC` parks it, you answer right there, and `/play` brings it back where
it was. With the CLI the agent is one pane away - switch, answer, come back.

</details>
<details>
<summary>tmux? zellij? Windows?</summary>

All three. Held keys feel best in a terminal that reports key releases;
[terminals](/terminals/) has the list and the fixes. For the
[pi extension](/pi/) the terminal that matters is the one pi runs in.

</details>
<details>
<summary>Is it free?</summary>

MIT-licensed, one static binary, no account.

</details>
<details>
<summary>Why is the logo lowercase?</summary>

Because it lives in a terminal.

</details>
</div>
