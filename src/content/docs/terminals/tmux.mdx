## what is going on

tmux does not implement the kitty keyboard protocol. What it *does* forward,
with `extended-keys on`, is xterm's `modifyOtherKeys` / fixterms-style
encoding for **modified** keys, and that encoding has no press / repeat /
release event type at all. No tmux option (`extended-keys`,
`terminal-features`, anything) can produce a key-release event through it,
whatever the outer terminal is. (See tmux issues
[#3335](https://github.com/tmux/tmux/issues/3335),
[#4158](https://github.com/tmux/tmux/issues/4158) and
[#4196](https://github.com/tmux/tmux/issues/4196).)

Because tmux also swallows the probe query, terminalika does not bother
probing: when the `TMUX` environment variable is present it goes straight to
the [auto-repeat fallback](/terminals/#the-fallback-synthesised-releases).
Auto-repeat passes through tmux normally, so the game is playable, only
sticky.

## what to do

- **Run terminalika outside tmux.** Open a plain terminal tab or window; the
  launcher is a standalone binary and needs nothing from the tmux session.
- Or keep tmux and accept the sticky feel; Snake and Tetris are barely
  affected, Pong and Invaders are.

## check for yourself

```sh
echo $TMUX              # non-empty inside tmux → fallback is used
terminalika --game=pong # warning screen names tmux
```
