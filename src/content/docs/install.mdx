terminalika comes in two forms. The **CLI** is a standalone launcher that
runs in the pane next to any agent and watches the agent's own transcript
(or takes a hook). The **extension** puts the same games *inside*
[pi](https://pi.dev), as an overlay - no second pane, no CLI needed.

| Method                                                          | CLI | Extension (pi) |
| --------------------------------------------------------------- | :-: | :------------: |
| [Homebrew](#package-managers) (macOS / Linux)                   |  ✓  |       -        |
| [Scoop](#package-managers) (Windows)                            |  ✓  |       -        |
| [`.deb` / `.rpm` / `.pkg.tar.zst` / `.apk`](#linux-packages)     |  ✓  |       -        |
| [Raw binary](#raw-binaries) (`tar.gz` / `zip`)                  |  ✓  |       -        |
| [`go install`](#package-managers) (Go 1.24+)                    |  ✓  |       -        |
| [`pi install`](#extension-pi)                                   |  -  |       ✓        |

## which one for your agent

Three stages: does the CLI detect the agent with nothing installed on the
agent side; what does the agent itself have to be told for the CLI; can the
games run inside the agent.

| Agent       | 1 · CLI, out of the box                                       | 2 · CLI, agent-side config                                                    | 3 · Extension inside the agent |
| ----------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------ |
| Claude Code | ✓ tails `~/.claude/projects`: end of turn, `AskUserQuestion`  | optional: [`Notification`/`Stop` hooks](/events/#claude-code-hooks) add permission prompts | - (Claude Code has no UI API)  |
| Pi Agent    | ✓ tails `~/.pi/agent/sessions`                                | none                                                                          | ✓ [pi-play](#extension-pi) (`/play`) |
| Aider       | ✓ tails `.aider.chat.history.md` (best effort)                 | recommended: [`--notifications-command`](/events/#aider)                       | -                              |
| Cursor CLI  | - (no session files)                                           | required: [`stop` hook](/events/#cursor-cli-hooks) → `terminalika notify`      | -                              |

## cli

Every release ships prebuilt packages and raw binaries on the
[GitHub releases page](https://github.com/terminalika/terminalika/releases).
Pick whichever fits your system; there is nothing else to configure.

Supported platforms: **Linux**, **macOS** and **Windows**, each in `amd64` and `arm64`.
On Windows you need Windows 10+ and a VT-capable terminal (Windows Terminal).

### linux packages

Direct downloads; no third-party repository or AUR needed. These links always
resolve to the latest release.

<Tabs syncKey="distro">
	<TabItem label="Debian / Ubuntu">
		```sh

		sudo apt install ./terminalika_amd64.deb
		```
	</TabItem>
	<TabItem label="Fedora / RHEL / openSUSE">
		```sh
		wget https://github.com/terminalika/terminalika/releases/latest/download/terminalika_amd64.rpm
		sudo dnf install ./terminalika_amd64.rpm
		```
	</TabItem>
	<TabItem label="Arch">
		```sh

		sudo pacman -U terminalika_amd64.pkg.tar.zst
		```
	</TabItem>
	<TabItem label="Alpine">
		```sh
		wget https://github.com/terminalika/terminalika/releases/latest/download/terminalika_amd64.apk
		```

`arm64` variants of every package are attached to each release too — file
names use the plain `amd64`/`arm64` pair for every format, not each distro's
native `x86_64`/`aarch64` spelling. Purely cosmetic: package managers read
the real architecture from the package metadata, not the file name.

### raw binaries

If you would rather not use a package: each release also attaches a `tar.gz`
(Linux, macOS) or `zip` (Windows) containing a single static `terminalika`
binary. Drop it somewhere on your `PATH`.

```sh
wget https://github.com/terminalika/terminalika/releases/latest/download/terminalika_linux_amd64.tar.gz
tar xzf terminalika_linux_amd64.tar.gz
install -m 755 terminalika ~/.local/bin/
```

## extension (pi)

```sh
pi install npm:@terminalika/pi-play
```

Then, while pi works:

```
/play            pick a game
/play snake      or name one: snake, tetris, 2048, mines
/play stop       end the game
```

The games ship as wasm inside the package and pause on pi's own
`agent_settled` event - nothing to configure, no CLI required. `ESC` parks
the game and hands the keyboard back to pi; `/play` brings it back exactly
where it was; `alt+g` picks another game from either side; `/play stop` is
the only way out. Needs pi 0.84+, on Node 22+ or Bun. The whole story - auto-pause
modes, `pi.json`, held keys, what the extension leaves to the CLI - is on
[pi extension](/pi/).

## updating

Neither form updates itself. Every install command on this page resolves to
the latest release, so updating is re-running the one you used:

| Installed with                     | Update with                                              |
| ---------------------------------- | -------------------------------------------------------- |
| Homebrew                           | `brew upgrade --cask terminalika`                        |
| Scoop                              | `scoop update terminalika`                               |
| Go                                 | `go install github.com/terminalika/terminalika@latest`   |
| a distro package (deb/rpm/zst/apk) | the same two lines from [linux packages](#linux-packages) |
| a raw binary                       | the same three lines from [raw binaries](#raw-binaries)  |
| `pi install`                       | `pi update`                                              |

`terminalika -version` prints what you are running; the
[releases page](https://github.com/terminalika/terminalika/releases/latest)
shows what is current. Your settings live in your config directory, which
no update path touches: the CLI's `config.json` and high scores, the
extension's [`pi.json`](/pi/#pijson).
